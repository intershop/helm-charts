_@Target Audience: Developer, Tester, DevOps, Ops_

== Description

Configures the transport and discovery technology used by http://www.jgroups.org/[JGroups] to communicate between `icm-as-server` pods. TCP with Kubernetes pod discovery is recommended for Kubernetes and Azure environments.

[cols="1,3,1,1,1",options="header"]
|===
|Attribute |Description |Type |Mandatory |Default Value
|transport|Transport used for JGroups cluster communication|enum {`tcp`, `udp`}|{optional}|`tcp`
|useVirtualThreads|Use Java virtual threads for JGroups transport tasks (requires Java 21+ and JGroups 5.5+)|bool|{optional}|`true`
|bindPort|First port used by the transport|int|{optional}|`7800`
|portRange|Number of additional ports available starting at `bindPort`; KUBE_PING probes the same range|int|{optional}|`5`
|udp.sendBufferSize|Requested UDP send buffer size in bytes|int|{optional}|`200000`
|udp.receiveBufferSize|Requested UDP receive buffer size in bytes|int|{optional}|`200000`
|discovery|Configures which discovery technology is used|enum {`file_ping`, `kube_ping`, `azure_ping` (_playground_), `dns_ping` (_playground_)}|{optional}|`kube_ping`
|location|If `discovery=file_ping`, this attribute configures where JGroups creates the necessary files (needs to be a file system shared between all `icm-as-server` pods)|path|{optional}|`/intershop/jgroups-share`
|clusterLabel|If `discovery=kube_ping`, this attribute configures the label of the `icm-as-server` cluster - all pods using this label belong to the same cluster|string|{optional}|[.placeholder]#release name#
|===

[NOTE]
====
If `discovery=kube_ping`, the `icm-as-server` containers require access to the Kubernetes API. The chart creates a service account when required and deploys a role granting access to pod listings.

The transport ports are declared on application-server and job-server containers. Network policies or firewalls must allow the selected transport protocol and the inclusive range from `bindPort` through `bindPort + portRange` between cluster pods. Kubernetes container port declarations do not open traffic in network policies.

UDP buffer values are requested socket-buffer sizes, not guaranteed allocations; the node OS can cap them. The defaults are intentionally conservative to avoid common Linux socket-buffer warnings. Increase them only if UDP traffic measurements indicate buffer drops or bursts that need more queue capacity, and align the values with the node's socket-buffer limits. These settings do not affect TCP.

The defaults change from FILE_PING over UDP to KUBE_PING over TCP. To preserve the previous stack during an upgrade, explicitly set both `jgroups.transport: udp` and `jgroups.discovery: file_ping`, and retain storage shared by all cluster pods. TCP and UDP members cannot communicate within the same JGroups cluster. When switching transport, stop all existing application-server and job-server pods before starting pods with the new transport instead of using a rolling update.
====

=== Example
[source,yaml]
----
jgroups:
  transport: tcp
  useVirtualThreads: true
  bindPort: 7800
  portRange: 5
  discovery: kube_ping
  udp:
    sendBufferSize: 200000
    receiveBufferSize: 200000
----
